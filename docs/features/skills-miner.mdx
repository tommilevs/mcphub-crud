---
title: Skills Miner
description: Evidence-backed draft workflow candidates, never automatic installation
---

The initial preview stage requires both `MCPHUB_SKILLS_MINER_ENABLED=true` and
`MCPHUB_EXPERIENCE_MEMORY_ENABLED=true`. Both default off. Admin
`POST /api/skills/preview` accepts an approved `experienceId` and optional `keyId`;
the owner is always the authenticated user, never request-body identity.

The source experience must still have current, retained, privacy-approved,
reviewed-correct results and reviewed successful task outcomes. Mining reads
result IDs, task/trace/branch, timestamps, tool identity and model-source labels;
it does not copy arguments or RAW into the candidate.

A candidate needs two independent tasks with the same multi-step server/tool
sequence. Each task must have a single known trace/branch, strictly ordered
timestamps and at least two reviewed calls. Duplicate result IDs, unknown branch,
ambiguous order, differing sequences or revoked sources are rejected. Scope must
apply to every step. One random successful call never creates a proposal.

The returned object is always a **draft proposal**. Timestamp order is explicitly
temporal evidence, not proof of causal ordering or a universally correct workflow.
It retains task/result IDs, the sequence signature, model-source observations,
applicability and reported version claims. Multiple model segments are not
credited to the last model. Unknown/self-reported identities remain labeled as
such; no model performance or generalized confidence is invented.

Preview includes a generated draft `markdown` with prerequisites, applicability,
observed steps, safety, result references, reported/unknown versions and explicit
limitations. It embeds neither RAW nor arguments and does not claim causal or
model-quality proof. Names/descriptions cannot inject frontmatter fields or HTML.

`POST /api/skills` saves a generated draft from `experienceId` and optional `keyId`.
`GET /api/skills?keyId=...` lists up to 50 proposals in that exact owner/key scope.
`PATCH /api/skills/:id` accepts `revision`, `status` and optional `markdown` (64 KiB
maximum). Every edit resets status to draft; approval is a separate request against
the exact revision. Concurrent changes have one winner and return 409 otherwise.
Each change atomically appends a version snapshot, preserving previous content.

`GET /api/skills/:id/versions?keyId=...&beforeRevision=...` reads saved revisions
in descending order, ten per page. `nextBeforeRevision` is an exclusive cursor;
missing and foreign proposals both return 404. The dashboard offers a read-only,
plain-text version viewer with older pages loaded on request. Historical approval
does not authorize exporting an old snapshot: the export endpoint always checks
the current proposal and current evidence. History remains available for owner
governance even when evidence no longer qualifies for export.

`POST /api/skills/:id/export` downloads the reviewed Markdown as `SKILL.md` only
when the proposal is approved and its source experience revision and reviewed
workflow remain current. Privacy revocation, missing evidence, retirement or changed
source revision block export. Listing stale proposals remains available for governance.
Approval does not make edited text trustworthy automatically: the reviewer must
inspect prerequisites, safety, privacy and applicability before approving.

The History dashboard's Experience Memory cards expose a lazy Skills Miner panel:
create a workflow draft, edit its Markdown, save, separately review/approve the
saved revision, retire it or download `SKILL.md`. Editing clears review confirmation;
unsaved changes cannot be approved or exported. API errors remain visible, including
disabled features and stale evidence. No Markdown is rendered as HTML in the editor.
No skill is installed or executed by these endpoints; no tool permissions are changed.
