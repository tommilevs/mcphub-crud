title: Experience Memory
description: Reviewed strategies with scoped, current source evidence
---

Enable `MCPHUB_EXPERIENCE_MEMORY_ENABLED=true` explicitly; default off. PostgreSQL
stores derived proposals separately from immutable tool results. No model weights,
tools or skills are modified or executed.

Admin `POST /api/experiences` accepts `title` (160 characters), `summary` (4000),
`taskType`, one `keyId` scope, 1–20 `evidenceIds`, optional `scope` with server/tool
lists, and `toolVersions` (operator-reported claims, not observed version proof).
`approved` defaults to false; drafts are not retrieved. Explicit approval requires
all source results to exist in the authenticated owner's/key scope, retain RAW,
have digest-matching approved privacy/correct-call reviews and current reviewed
successful task outcomes. Execution status alone is never an outcome label.

`GET /api/experiences/search?q=diagnostic&limit=10` returns approved proposals in
the caller's owner/key scope, with optional `taskType` and `keyId`. PostgreSQL
full-text retrieval uses title, summary and task type; up to 100 candidates are
rechecked against current source reviews before returning at most 20. Removed,
revoked or no-longer-successful evidence hides a proposal until it is reviewed
again with suitable evidence. Stored source IDs and the creation-time evidence
snapshot remain auditable; they do not override current privacy decisions.

One reviewed task supports only a **hypothesis**. Two distinct reviewed task IDs
receive the **supported** label, meaning multiple user-confirmed examples—not
statistical confidence, independent verification of the rule, or proof of
generalization. Multiple calls in the same task do not multiply task evidence.
Scope and version claims must be considered before using a strategy elsewhere.

`PATCH /api/experiences/:id/status` accepts the current `revision`, `keyId` and
`status` (`draft`, `approved`, `retired`). Every change is atomically audited;
concurrent stale updates return 409. Approval rechecks evidence. Retirement works
even if evidence expired. Local experience retrieval is a different purpose from
training export; task training consent is not silently inferred or granted.

This slice provides reviewed proposal storage, audit and lexical retrieval API.
Automatic extraction, editing proposal text in place, hybrid vector retrieval and optional Basic Memory
adapter remain subsequent work.
These entries are advice, never new permissions or commands to execute.

## Scoped LoopGuard advice

Additionally enable `MCPHUB_EXPERIENCE_ADVICE_ENABLED=true` to retrieve at most three
current experiences after a deterministic LoopGuard warning. Both experience
flags are required. Owner/key isolation and current source privacy/outcome checks
still apply. Explicit `scope.servers` and `scope.tools` constraints must match;
tool scope uses the exact `server/tool` name. Malformed scope never broadens it.
Manual search also accepts paired `server` and `tool` filters.

Runtime does not independently know historical/current tool versions, so entries
with version constraints are not automatically suggested. Without an explicit
task classification, only `general` entries qualify. A source's successful task
does not prove that its strategy generalizes to a different category.

The current call receives reviewed titles/summaries and evidence references in
LoopGuard metadata. Persistent warning state stores only experience ID/revision,
confidence and result references, not copied strategy text that could outlive a
source privacy withdrawal. Existing client responses cannot be recalled. Retrieval
failure leaves deterministic advice intact; no execution permission is added.
Internal ToolPilot still receives metadata-only input and does not send these
strategy texts to its model provider.

## Review dashboard and current references

History contains a lazy-loaded Experience Memory panel. Select 1–20 results to
create a proposal, describe applicability, and explicitly approve it or leave it
as a draft. Editing proposal fields, evidence selection or key scope clears the
approval checkbox. Search reads approved/current proposals; loading your proposal
list includes drafts, retired entries and stale evidence for governance. Invalid
evidence prevents approval, while retirement remains possible. Status changes
use the displayed revision and never execute the described workflow.

Admin `GET /api/experiences` lists at most 50 own proposals, optionally filtered
by status/key. This management view is not agent advice and explicitly exposes
stale assessment for review. `GET /api/experiences/:id` instead returns only an
approved entry with current valid evidence in the authenticated owner/key scope;
missing, foreign, retired or stale entries return 404. Historical LoopGuard
references use this current-read API on demand instead of storing strategy text
in warning history. `GET /api/experiences/available` reports the feature flag.
